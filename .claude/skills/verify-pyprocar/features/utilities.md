# File utilities

Small one-call helpers exported at top level (`pyprocar/scripts/__init__.py`) that read or write VASP-style files rather than plot: band gap, KPOINTS generation, PROCAR filter/repair/merge, and a 2D k-grid.

## Sub-features

- Band gap: `pyprocar.bandgap(dirname=..., code="vasp", fermi=None)` returns the gap in eV, 0.0 when a band crosses E_F (`scripts/scriptBandGap.py`). Pass `dirname` by keyword: the first positional parameter is the unused `procar`.
- k-path: `pyprocar.kpath(infile="POSCAR", outfile="KPOINTS", grid_size=40)` writes a line-mode KPOINTS via seekpath and returns `(k_path, k_labels)` (`scriptKpath.py`). `infile` has no default.
- PROCAR filter: `pyprocar.filter(inFile, outFile, atoms= | orbitals= | bands=[min,max] | kpoints=[min,max] | spin=)`. Only the first non-empty selector applies (`scriptFilter.py`).
- PROCAR repair: `pyprocar.repair(infile, outfile)` (`scriptRepair.py`).
- PROCAR merge: `pyprocar.cat(inFiles=[...], outFile="PROCAR_merged", gz=False)`; with `gz=True` it writes `<outFile>.gz`. It globs `PROCAR_*` in the CWD when `inFiles` is None. `mergeparallel`/`fixformat` are Abinit paths, which are not driven (`scriptCat.py`).
- 2D k-grid: `pyprocar.generate2dkmesh(x1, y1, x2, y2, z, nkx, nky)` returns an `(nkx*nky, 3)` array and **always writes `./Kgrid.dat` into the CWD** (`scriptKmesh2D.py`).
- `spin_asymmetry` is still exported, but it is a deprecated stub that always raises `NotImplementedError`.
- `autobandsplot(code=, dirname=, report=)` is exported and returns `None`. The driver does not run it; the `report=` claim below comes from `tests/pyprocar/scripts/test_auto_bandsplot.py`.
- Test-data download: `pyprocar.download_from_hf(relpath, output_path=Path(...))` and the installed `pyprocar-download --relpath <relpath> [--output-path <dir>]` CLI (`scripts/download.py`) download `<relpath>.zip` from the HF dataset and unzip it. `$H fetch` wraps the function.
- CLI: `python scripts/procar.py <subcommand>`, with subcommands `cat`, `filter`, `repair`, `fermi2D`, `bandgap`, `generate2dkmesh`, `kpath`, `unfold` and `bandsplot`. It is not installed as a command. `unfold` is a band plot; see `bands.md`.

## How to get to it (user POV)

`import pyprocar`, then call the function from a shell or notebook inside the calc dir. Relative paths resolve against the CWD.

## Driving it with verify.sh

```bash
$H run utilities data/examples/bands/non-spin-polarized .claude/skills/verify-pyprocar/scripts/examples/utilities.py
```

The driver `chdir`s into `CALC` so every output lands in the calc copy and shows up in `side_effects.txt`. Nothing should appear in the repo root.

The proven end state (SrVO3, non-spin-polarized, c13166ce, driven 2026-10-05):
- `bandgap`: returns 0.0 eV, as it should for metallic SrVO3.
- `kpath`: a 23-line `KPOINTS_pyprocar`, `40 ! Grid points`, `Line_mode`, with the cubic path Γ–X–M–Γ–R–X | R–M.
- `filter_bands` with `bands=[1,5]`: the header reads `# of bands: 5`, and the file shrinks from 2,404,492 to 602,689 bytes.
- `repair`: 2,363,890 bytes, with a valid `PROCAR lm decomposed` header.
- `cat` of the PROCAR with itself: one header with `# of k-points: 400`.
- `cli_cat_gz`: `procar.py cat PROCAR PROCAR cli_merged --gz` writes `cli_merged.gz`. `cli_filter_atoms`: `procar.py filter PROCAR cli_atoms -a 0 1 -a 2` writes `# of ions: 2`. The driver runs `procar.py` in-process through `runpy`, so a crash keeps its traceback.
- `spin_asymmetry`, `download_from_hf_str_output_path`, `cli_bandgap` and `cli_generate2dkmesh` crash; see Gotchas.
- `scripts/procar.py` (#285, `tests/test_procar_cli.py`): `cat a b out [--gz]` merges to 400 k-points. `filter in out -a 0 1 -a 2` writes `# of ions: 2` with the first row the sum of atoms 0 and 1, and `--human`, `-o ... --orbital_names`, `-b` and `-s` run too (before #285 every `filter` call raised `AttributeError: 'Namespace' object has no attribute 'infile'`). `fermi2D <dir> -f 5.3017 --savefig fs.png [--mode parametric -a 1 -o 4 5 6 7 8]` draws the SrVO3 slice.
- `autobandsplot(..., report=path)` writes its analysis report to `path` only; with the default `report=None` it writes no file (#285). On `data/examples/bands/auto` the report equals the fixture's own `report.txt`.
- `generate2dkmesh(-0.5,-0.5,0.5,0.5,0,5,4)`: shape `[20, 3]`, and `Kgrid.dat` starts `Generated by PyProcar / 20 / Reciprocal`.
- A filtered PROCAR plots (#293, `tests/pyprocar/scripts/test_filtered_procar.py`). With `atoms=[[0],[1],[2,3,4]]` the PROCAR has 3 rows next to the 5-atom POSCAR. The parser warns and sets `ebs.atom_groups = 3`. `bandsplot(mode='parametric', atoms=[2])` draws the same colours as `atoms=[2,3,4]` on the unfiltered PROCAR. Species selections (`atoms=['O']`, `overlay_species`, `items`) raise `Cannot select species 'O'`. With `orbitals=[[0],[1,2,3]]` the columns are labelled `o0` and `o1`, and `orbitals=['p']` raises `hold no whole p shell`. On the irreducible k-points of `data/examples/fermi2d/non-spin-polarized`, `fermi2D` of an atom-filtered PROCAR raises `filtered by atoms cannot be unfolded`, because ibz2fbz (#299) permutes atoms between rows the file no longer names. A structure-less DOS (every Lobster DOS) sums every atom row when a selection names no atoms: `dosplot(code='lobster', mode='parametric', orbitals=[1,2,3])` colours by the p weight of all atoms.
- `side_effects.txt`: `KPOINTS_pyprocar`, `PROCAR_bands_1_5`, `PROCAR_repaired`, `PROCAR_merged`, `Kgrid.dat`, `cli_merged.gz`, `cli_atoms`. `bandgap` writes nothing.

## Gotchas

These are product gaps at c13166ce. Record them; don't route around them.
- **`download_from_hf` and `pyprocar-download` fail when the output path is a str**, which is the default `"."` of both. `download_test_data` runs `output_path / relpath` before it converts `output_path` to a `Path` (`pyprocar/utils/download_examples.py:143`): `TypeError: unsupported operand type(s) for /: 'str' and 'str'`. The CLI passes its `--output-path` str, catches the error, prints `Download failed`, and exits 1 for every relpath. Pass a `Path`, as `$H fetch` and the notebooks do.
- **`procar.py bandgap` cannot run.** It passes its four positionals to `bandgap(procar, dirname, outcar, code, ...)` in that order (`scripts/procar.py:124`), so the code is the Fermi string: `ValueError: Invalid code: 5.3017` at `pyprocar/io/__init__.py:45`. It also takes no directory.
- **`procar.py generate2dkmesh` cannot run.** Its positionals have no `type=`, so strings reach `np.linspace`: `TypeError: 'str' object cannot be interpreted as an integer` at `pyprocar/scripts/scriptKmesh2D.py:42`.
- `procar.py kpath` has `-with_time_reversal` as a `store_true` flag that defaults to False, while `kpath()` defaults to True, and it always writes `./KPOINTS` (source only).

- `generate2dkmesh` writes to the CWD with no path argument. Run it from a scratch dir, never from the repo root.
